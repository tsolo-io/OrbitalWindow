# 0018 File manager, group folders, scratch and soft quotas

- Status: accepted
- Date: 2026-10-09

## Context
Phase 4 of the design: a web file manager per user, group/project folders, a shared scratch
folder, disk usage with soft quotas and a nightly clean-up. [0013](0013-files-sharing-and-remote-access.md)
recorded the choices; this record covers how they were built and where they differ from the design.

## Decision
- **FileBrowser Quantum `2.0.0-stable-slim`** (released 2026-10-09; the design expected a v2 beta).
  Fallback if it misbehaves: `1.5.8-stable`, then the minimal page from the design.
  - One container `ow-files-<user>`: runs as the user's UID with the user's group GIDs
    (`group_add`), read-only root filesystem, all capabilities dropped, 512 MB memory limit.
    Port 8080 (unprivileged); the healthcheck is overridden because the image's own one assumes
    port 80.
  - Config generated by OrbitalWindow (`state/files-config/<user>.yaml`): one source per mount
    (home, each group, scratch, shared data read-only), proxy-header login with `X-OW-User`,
    password login off, no share links, WebDAV off.
  - FileBrowser's built-in admin is renamed to `ow_fb_admin` with a random password: by default it
    is `admin`/`admin`, which would collide with OrbitalWindow's first admin `admin` via the header.
  - **Deviation:** the file manager gets **its own network `ow-fnet-<user>`**, joined only by Traefik,
    instead of sharing `ow-net-<user>` with the desktop. FileBrowser trusts the header blindly, so
    anything that can reach it directly can claim any name (including the built-in admin). On its
    own network only Traefik, which overwrites the header after forwardAuth, can reach it.
  - `/files/<user>/` is protected by forwardAuth `/auth/files` (owner only, same rules as desktops).
  - Lifecycle: created with the user, stopped while disabled, removed with the user; recreated when
    the user's groups change. The reconcile loop keeps every enabled user's file manager running
    and recreates it when its spec changes (a hash label).
- **Group folders** `$OW_ROOT/groups/<name>`: `root:<gid>`, mode `2770`, default ACL `g::rwX`, so
  files members create stay group-writable. GIDs are 3000+N from a never-reused counter. Group and
  user names share one namespace (both are Samba shares).
  - Desktops mount `/groups/<name>`; the init hook creates the groups from `OW_GROUPS` and adds `abc`.
    **Verified:** s6 keeps the supplementary groups for every desktop process, so `group_add` on the
    desktop container is not needed (open point in the design, closed).
  - Samba: `[<group>]` with `valid users = @<group>`, `force group`, masks 0664/2775.
  - Membership changes update Samba and the file managers at once. A running desktop keeps its old
    groups until restarted; the dashboard says so (container label `ow.groups`).
  - The helper container needs `CAP_FSETID`: without it, setting the ACL as root (not a member)
    clears the setgid bit.
- **Scratch** `$OW_ROOT/shared/scratch` (mode 1777): `/scratch`, the file manager, and `[scratch]` in
  Samba for all users. The sticky bit protects files from other users' normal accounts, but not
  from `sudo` inside a desktop (root there has `CAP_FOWNER`/`CAP_DAC_OVERRIDE` on the bind mount),
  so scratch is documented as shared, not private. A `README-auto-clean.txt` explains the clean-up and is rewritten when the
  retention changes. Every night after 02:00 (service time zone) a helper container deletes files
  untouched for N days (setting, default 30) and then empty folders.
- **Disk usage**: hourly, a helper container runs `du -sxb` over homes, group folders and scratch
  and stores `disk_usage`. Soft quotas (`users.quota_gb`, `groups.quota_gb`): warning at ≥90% on the
  dashboard; the admin System page lists everyone largest first, with host free space and a warning
  at ≥85% full. Nothing is enforced.
- Scheduled jobs run in the reconcile loop; their last run times are stored in `settings`.

## Consequences
- Each user has up to two networks (desktop and file manager) with Traefik attached to both.
- A running file manager uses about 20 MB of RAM per user when idle (measured on the VM).
- Disk numbers are up to an hour old ("Measure now" on the System page refreshes them).
