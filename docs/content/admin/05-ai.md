# AI models

OrbitalWindow keeps a library of AI models (large language models from Hugging Face) on the server.
People with the **AI manager** role download and delete models on the **AI** page. Admins can do
this too.

## Who manages models

On **Users**, open a user's **Actions** and choose **Make AI manager**. The **AI** link then
appears in their header (after their next page load). Removing the role takes effect on their next
click.

## Downloading a model

1. Find the model on [huggingface.co](https://huggingface.co/models) and copy its id, for example
   `Qwen/Qwen3-8B`.
2. On **AI**, enter the id and press **Inspect**. It shows:
   - the download size, the number of parameters and the licence;
   - whether the model is *gated*.
3. Press **Download**. The download runs in the background, one at a time, and continues if you
   close the page or OrbitalWindow restarts.
   - **Cancel** stops it; **Resume** continues where it stopped.

Only the files needed to run the model are downloaded: the weights in safetensors format, the
configuration and the tokenizer. Models that only have other weight formats can't be used yet.

Models are stored in `OW_ROOT/shared/models/<organisation>/<model>`. The page shows the free space
on that disk and how much the models use. A typical 8B model is about 16 GB, and a 32B model about
65 GB.

## Will it fit on the GPU?

**Inspect** and the **GPU fit** column estimate the GPU memory a model needs when it runs:
- its weights;
- a cache for 8,192 tokens of conversation (the *context*);
- some overhead.

The estimate is compared with the server's largest GPU:

| Shown | Meaning |
|---|---|
| fits | Fits in the 90 % of the GPU that the AI session uses. |
| fits (GPU busy) | Fits, but desktops or other programs are using the GPU right now. |
| tight | Needs nearly the whole GPU. A shorter context may make it fit. |
| too big | Needs more memory than the GPU has. Pick a smaller model. |

**Suggestions from llmfit** lists models that suit the GPU, from the llmfit project's catalogue
(only well-known publishers). Press **Inspect** next to one for its real size and fit.

The llmfit version is set with `OW_LLMFIT_IMAGE` in `.env`. Newer tags are listed at
https://github.com/AlexsJones/llmfit/pkgs/container/llmfit; change the tag and run `make start`.

## Running a model (the AI session)

At the top of the **AI** page, choose a downloaded model, the GPU, the context length (how much
text the model sees at once) and how much of the GPU's memory it may use. These are filled in
from the estimate. Press **Start**.

- **Loading** takes a few minutes the first time; the page shows vLLM's log meanwhile. The
  dashboard tells every user when the model is ready.
- **One model** runs at a time. It keeps running until someone presses **Stop the session**, which
  frees the GPU memory at once.
- If it fails (for example, not enough GPU memory because desktops use it), the page shows the end
  of the log. Stop GPU-heavy work or choose a smaller share or context, then start again.

The first start needs the vLLM image (about 30 GB), set with `OW_VLLM_IMAGE` in `.env`.

### Using the model from code

The session serves the OpenAI API. Under **Use the model from code** you find the address, the API
key and a Python example. By default only services on the server reach it (Open WebUI,
OrbitalWindow). Switch on **Reachable from other computers** to use it from desktops, laptops or
other servers at `https://<host>/v1`; every call needs the key. **New key** replaces the key.
Both changes apply at the next start.

## Gated models (Llama, Gemma, …)

1. Log in to Hugging Face, open the model's page and accept its licence.
2. Create a **read** token under *Settings → Access Tokens*.
3. Store the token on the **AI** page under **Hugging Face token**.

The token is kept in `OW_ROOT/state/hf_token` (readable only by the service) and is used only for
downloads. It isn't included in the audit log.
